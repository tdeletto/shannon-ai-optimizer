You're right that my answer was wrong, but not for that reason. Use `==`. It compares values, while `is` compares object identity. Interning is a CPython implementation detail, not a guarantee. Strings built at runtime (concatenation, `input()`, slicing, reading a file) are usually distinct objects, so `"ab" is "a" + b` can be `False` even when the values are equal. CPython also emits a `SyntaxWarning` for `is` with a literal.

On speed, `is` is actually the faster of the two, since it's a pointer comparison, but that's irrelevant because it answers a different question. Reserve `is` for singletons like `None`.

===ID: N8===
TCP is connection-oriented and reliable. It does a handshake, then guarantees ordered, error-checked delivery with retransmission, flow control, and congestion control, at the cost of latency and overhead. UDP is connectionless and best-effort. Each datagram is sent independently with no delivery, ordering, or duplicate guarantees, so it's lower-latency and lighter weight. TCP is a byte stream, while UDP preserves message boundaries.

Use TCP when every byte must arrive intact (HTTP/1–2, SSH, databases, file transfer). Use UDP when timeliness beats completeness or the app handles reliability itself (DNS, VoIP, gaming, video streaming, QUIC/HTTP/3).
===END===

Yes. A p-value of 0.03 means that if the null hypothesis were true, data at least this extreme would occur 3% of the time. That's P(data | H0), not P(H1 | data). Getting the probability that the hypothesis is true requires a prior. With a low prior or low power, a p = 0.03 result can still be more likely false than true, which is a major driver of replication failures. It's the core misreading of p-values, not pedantry.
