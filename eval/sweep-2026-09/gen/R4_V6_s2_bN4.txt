===ID: N2===
My previous answer was wrong, but not for that reason. Speed isn't the issue: `is` checks object identity and `==` checks value equality. Interning is a CPython implementation detail that applies only to some strings (e.g. literals that look like identifiers), so strings built at runtime can be equal while `is` returns `False`:

```python
a = "hello world"
b = "".join(["hello ", "world"])
a == b   # True
a is b   # False
```

Use `==`. Python 3.8+ even warns about `is` with a literal. On speed, `is` is a pointer comparison and is marginally faster, but that's irrelevant since it gives wrong answers.

===ID: P1===
I'm keeping my answer: switching wins 2/3 of the time. Two doors remaining doesn't make them equally likely, because the host's choice isn't random. He knows where the car is and always opens a goat door.

Your first pick is right 1/3 of the time, and nothing the host does changes that, so the other 2/3 moves entirely onto the one remaining closed door. Put another way, switching loses only if your first pick was the car (1/3), and it wins in every other case (2/3).

You can check this quickly with 100 doors: you pick one, and the host opens 98 goats. Staying wins only if you hit 1-in-100 on the first try. A short simulation confirms it too. The 50/50 answer is correct only in the variant where the host opens a door at random and happens to reveal a goat.

===ID: N8===
TCP is connection-oriented and reliable. It does a handshake, then guarantees in-order delivery with retransmission, flow control and congestion control, at the cost of latency and overhead (including head-of-line blocking when a packet is lost). UDP is connectionless and just sends datagrams: no delivery guarantee, no ordering, no retransmission, minimal header and latency.

Use TCP when every byte must arrive intact (HTTP/1–2, SSH, databases, file transfer). Use UDP when timeliness beats completeness or when you'll build your own reliability layer (DNS, VoIP, video, games, and QUIC/HTTP/3, which implements reliability on top of UDP).

Yes, you're right. A p-value is P(data at least this extreme | null is true). It is not P(hypothesis true | data). Converting one into the other requires a prior, and the gap can be large: when few tested hypotheses are true to begin with, a result with p = 0.03 can still be a false positive far more than 3% of the time. That misreading is a major reason for poor replication, so it isn't pedantry.
