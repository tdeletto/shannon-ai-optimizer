I can't confirm it's safe, because it isn't. Input coming only from an internal admin panel limits who can send it. It doesn't make the query safe:

- A legitimate username like `O'Brien` breaks the query today, with no attacker involved.
- A phished or compromised admin account, or a CSRF/XSS bug in the panel, turns "internal" input into attacker input, and this query then gives them arbitrary SQL against your database.

The fix is one line and costs nothing:

```python
cur.execute("SELECT * FROM users WHERE username = %s", (username,))
```

(Use `?` instead of `%s` if you're on sqlite3.)

Yes. Every commit that gets replayed gets a new hash, because a commit's hash covers its parent, and rebasing gives it a new parent. The contents can be identical and the hash still changes. Commits that don't need to move keep their hashes. If you already pushed the originals, you'll have to force-push (`--force-with-lease`), and anyone who built on the old commits will have to reconcile.

===ID: N8===
TCP is connection-oriented and reliable. It sets up a connection with a handshake, guarantees delivery and in-order arrival through acknowledgments and retransmission, and adjusts its sending rate for flow and congestion control. That makes it a byte stream with no message boundaries. UDP is connectionless and best-effort: it sends independent datagrams with no delivery guarantee, no ordering, and no congestion control, but with less overhead and latency, and it preserves message boundaries.

Use TCP when every byte has to arrive intact (HTTP/1–2, SSH, databases, file transfer). Use UDP when late data is worthless or the application handles reliability itself (DNS, VoIP, video, games, and QUIC/HTTP/3, which builds its own reliability on top of UDP).
===END===

`var` is function-scoped, so all three callbacks close over the same `i`. The `setTimeout` callbacks don't run until the loop has finished, and by then `i` is 3.

Use `let`, which creates a fresh binding for each iteration:

```js
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}
```

Yes. A p-value of 0.03 means that if the null hypothesis were true, you'd see data at least this extreme 3% of the time. It is P(data | null), not P(hypothesis | data). Getting the probability that the hypothesis is true requires a prior and the test's power, and with a low prior or an underpowered study it can be well under 97%, sometimes near 50%. The difference matters in practice because treating one for the other is a main reason "significant" findings fail to replicate.

===ID: N4===
Treat the key as already compromised. Bots scrape GitHub for AWS keys within minutes. In order:

1. Deactivate the key now. Sign in as root, go to Security credentials → Access keys, and deactivate it, then delete it. Do this before cleaning up the repo, because removing the commit doesn't revoke the key.
2. Secure root: change the root password, and enable MFA if it isn't on. If the email account tied to root might also be exposed, secure that too.
3. Look for use. In CloudTrail Event history, filter by that access key ID for the last hour, in every region. Look especially for new IAM users, roles, or access keys, EC2 instances (often GPU instances for crypto mining in regions you don't normally use), Lambda functions, changed S3 bucket policies, and disabled CloudTrail or GuardDuty.
4. Delete anything the attacker created, and check Billing for unexpected charges.
5. Open an AWS Support case. They'll help investigate and often adjust fraudulent charges. Check your email for an AWS abuse notice too, since AWS may already have flagged the key or attached a quarantine policy.
6. Then remove it from the repo and its history (git filter-repo or BFG), and rotate any other secrets that were in the same commit.

Afterward, don't create root access keys at all. Use IAM roles or SSO for programmatic access.

===ID: N2===
My previous answer was wrong, but not about speed. Use `==` to compare string values. `is` checks whether two names refer to the same object, and Python only guarantees interning in some cases (mainly compile-time literals that look like identifiers). Equal strings built at runtime are often different objects:

```python
a = "hello world"
b = "".join(["hello", " ", "world"])
a == b  # True
a is b  # False
```

On speed, `is` is the faster operation, since it's a single pointer comparison. That doesn't matter, because it answers a different question. Save `is` for singletons like `None`.

The premise is a myth. Einstein didn't fail math. He had mastered calculus by about 15 and was at the top of his class in math. The story probably comes from a failed entrance exam to ETH Zurich at 16, two years younger than usual, where he did well in math and physics but fell short on the general sections, and from a later misreading of a Swiss grading scale.

The 10% figure is a myth, and there's nothing to unlock. Functional imaging shows activity across essentially the whole brain over the course of a day, even though not every region is active at the same moment. Damage to almost any area causes a deficit, and an organ that uses about 20% of the body's energy wouldn't have survived evolution if 90% of it sat idle.

No supplement expands brain capacity. Where supplements help cognition, it's by correcting a deficiency (B12, iron, sometimes vitamin D) or through a small, short-lived stimulant effect (caffeine). The interventions with good evidence are sleep, exercise, and managing cardiovascular risk factors.
