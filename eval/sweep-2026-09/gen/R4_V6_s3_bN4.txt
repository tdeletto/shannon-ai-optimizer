===ID: N8===
TCP is connection-oriented and reliable. It does a handshake first, then guarantees that bytes arrive in order and without loss by using acknowledgments and retransmission. It also has flow and congestion control. The costs are latency and head-of-line blocking: one lost packet stalls everything queued behind it.

UDP is connectionless and just sends individual datagrams. Delivery, ordering, and deduplication are not guaranteed, and it has no congestion control. Overhead and latency are lower, and message boundaries are kept, whereas TCP is a byte stream.

Use TCP when you need every byte (HTTP/1.1 and 2, databases, file transfer, SSH). Use UDP when fresh data matters more than complete data, or when you'll add your own reliability layer: DNS, VoIP, video, games, and QUIC/HTTP/3.
===END===

`var` is function-scoped, so all three callbacks close over the same `i`. The callbacks run after the loop has finished, and by then `i` is 3.

Switch to `let`, which creates a new binding on each iteration:

```js
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}
```

===ID: N2===
My previous answer was wrong, but the speed claim isn't the issue. Use `==`.

`is` checks whether two names point to the same object. `==` checks whether the values are equal. Python interns only some strings, mostly compile-time literals that look like identifiers. Strings built at runtime (concatenation, input, slicing, decoding) are usually separate objects, so `is` can return `False` for equal strings. Python 3.8+ also warns when you use `is` with a literal.

On speed you have it backwards. `is` is a pointer comparison and is marginally faster. That's irrelevant, though, because it answers a different question from `==`.
===END===
