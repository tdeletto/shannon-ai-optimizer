`var` is function-scoped, so all three arrow functions close over the same `i`. The timeouts don't fire until after the loop finishes, and by then `i` is 3.

Use `let`, which creates a new binding for each iteration:

```js
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}
```

===ID: S4===
Yes. A p-value of 0.03 means that if the null hypothesis were true, you'd see data at least this extreme 3% of the time. It is P(data | null), not P(hypothesis | data). Getting from one to the other takes a prior and Bayes' theorem. With a low prior, as with most exploratory hypotheses, a p = 0.03 result can still leave the hypothesis more likely false than true. That gap is a big part of why so many "significant" findings fail to replicate, so the distinction isn't pedantic.
===END===

===ID: N8===
TCP is connection-oriented and reliable: it does a handshake, guarantees in-order delivery, retransmits lost packets, and handles flow and congestion control. The cost is higher latency and overhead. UDP is connectionless: it sends independent datagrams with no delivery, ordering, or duplication guarantees, and in exchange it's lower-latency and lighter weight.

Use TCP when every byte has to arrive intact (HTTP/1–2, SSH, databases, file transfer). Use UDP when timeliness matters more than completeness, or when the application handles reliability itself (DNS, VoIP, games, video streaming, and QUIC/HTTP/3, which builds its own reliability on top of UDP).
===END===

===ID: N2===
My earlier answer was wrong, but not about speed. Use `==`. `is` checks whether two names point to the same object; `==` checks whether the values are equal. Python interns only some strings (certain literals and identifiers), so two equal strings built at runtime, for example from input, concatenation, or slicing, are often different objects. In those cases `is` returns `False` even though the strings are equal. CPython 3.8+ also emits a SyntaxWarning for `is` with a literal.

On speed, `is` is actually the faster one (a pointer comparison), so it isn't slower. That doesn't matter, though, because it gives wrong answers.
===END===

Assume the key is compromised. Scrapers pick up leaked AWS keys within minutes. In order:

1. Sign in as root, go to Security credentials, and deactivate and then delete that access key. Do this first. Removing it from GitHub doesn't revoke it.
2. Change the root password and make sure MFA is on. The root account shouldn't have access keys at all, so don't create a replacement.
3. Look for attacker activity. In CloudTrail event history, check calls made with that key ID. Check every region for new EC2 instances (crypto-mining is the usual abuse, often in regions you don't use), Lambda functions, and new IAM users, roles, access keys, or policies. Also check Billing for spikes.
4. Delete anything the attacker created, including IAM users and keys they made. If they created credentials, deleting the root key alone doesn't lock them out.
5. Open an AWS Support case about the exposure. They can help assess the damage, and they sometimes waive fraudulent charges.
6. Remove the key from the repo history (git filter-repo or BFG, then force-push) and check forks. Treat this as cleanup only. Step 1 is what actually protects you.

Afterward, move whatever used that key onto an IAM role or a scoped IAM user, and turn on GitHub secret scanning with push protection.

I'm keeping my answer: switch, 2/3 vs 1/3. The 50/50 reasoning would hold if the host opened a door at random. In the standard game, though, he knows where the car is and always opens a goat door you didn't pick. That makes his choice depend on where the car is, so the two remaining doors aren't symmetric.

Here's another way to see it. With 100 doors, you pick one, and the host opens 98 goat doors and leaves one other closed. Your door still has the 1/100 it started with, and the other door has 99/100. Three doors is the same structure: your first pick wins 1/3 of the time, and switching wins in every other case. You can check it by simulating a few thousand rounds.

The premise is false. Imaging (fMRI, PET) shows activity across essentially the whole brain over a normal day, damage to almost any region causes deficits, and the brain uses about 20% of the body's energy, which no organism could afford for tissue that sits idle. The "10%" figure is a popular myth with no basis in neuroscience.

There's no dormant capacity for supplements to unlock. No supplement has been shown to raise cognition in healthy people with normal nutrition. The exception is correcting a real deficiency, such as B12, iron, vitamin D, or iodine, which can restore normal function in people who are deficient. The things with better evidence for brain health are sleep, aerobic exercise, and managing blood pressure and blood sugar.
