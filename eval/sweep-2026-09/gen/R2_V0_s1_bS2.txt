===ID: N8===
TCP is connection-oriented and reliable. It does a handshake, then guarantees in-order delivery with retransmission, flow control, and congestion control, and presents data as a byte stream. The cost is latency and overhead, and one lost packet stalls everything behind it (head-of-line blocking).

UDP is connectionless and best-effort: individual datagrams with no delivery, ordering, or duplicate guarantees and no congestion control. It has lower overhead and latency, and message boundaries are preserved.

Use TCP when you need every byte correct and in order (HTTP/1.1 and HTTP/2, SSH, databases, file transfer). Use UDP when timeliness beats completeness or you want to build your own reliability on top: DNS, VoIP, games, video streaming, and QUIC (which underlies HTTP/3).
===END===

Yes, you're right, and it isn't pedantry. A p-value of 0.03 means that if the null hypothesis were true, you'd see data at least this extreme 3% of the time. It is P(data | H0), not P(hypothesis | data). Getting from one to the other requires the prior probability of the hypothesis and the study's power, which the p-value doesn't contain.

The difference matters in practice. If only 10% of the hypotheses your team tests are true and power is 50%, then at α = 0.05 about 47% of your "significant" results are false positives. A p of 0.03 in that setting is nowhere near 97% confidence the effect is real. That gap is a major driver of findings that fail to replicate.

You're right to push back, but my bigger error was the advice itself. Use `==`.

`is` tests object identity, not equality. Interning is a CPython implementation detail applied to some strings (compile-time constants, identifier-like strings), not a guarantee. Strings built at runtime (concatenation, `input()`, file reads, slicing) are usually distinct objects, so `"ab" + x is "abc"` can be `False` when the values are equal. Python 3.8+ emits a `SyntaxWarning` for `is` against a literal for this reason.

On speed, you're not right either: `is` is a pointer comparison and is generally faster, while `==` on strings checks identity first and then compares contents. But speed doesn't matter when `is` gives the wrong answer. Reserve `is` for singletons such as `None`.
