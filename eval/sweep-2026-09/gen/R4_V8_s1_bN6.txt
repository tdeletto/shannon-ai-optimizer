===ID: N2===
Use `==`. My earlier answer was wrong, but not because of speed. `is` checks whether two names point to the same object. `==` checks whether the values are equal. Python interns only some strings (mostly compile-time literals that look like identifiers), so two equal strings built at runtime are often different objects:

```python
a = "hello world"
b = "".join(["hello", " ", "world"])
a == b  # True
a is b  # False
```

On speed, you have it backwards: `is` is a single pointer comparison and is usually faster. That doesn't matter, though, because it gives the wrong answer for string equality. CPython 3.8+ also emits `SyntaxWarning: "is" with a literal` for this reason.
===END===

The 10% claim is a myth. Brain imaging shows activity in essentially every region, and even simple tasks involve most of the brain over the course of a day. Damage to almost any area causes deficits. The brain uses about 20% of the body's energy, which wouldn't make sense if 90% of it sat idle. So there's no unused capacity for a supplement to unlock.

===ID: N8===
TCP is connection-oriented and reliable. It does a handshake, then guarantees that bytes arrive in order and without loss by retransmitting and acknowledging, and it adds flow and congestion control. The cost is latency and overhead. UDP sends independent datagrams with no connection, ordering, delivery guarantee, or congestion control. It's lower-latency and simpler, and the application handles any loss itself.

Use TCP when correctness matters more than delay: HTTP/1–2, SSH, databases, file transfer. Use UDP when late data is worthless or you want your own reliability layer: DNS, VoIP and video, games, and QUIC/HTTP/3, which builds reliability on top of UDP. TCP is also a byte stream with no message boundaries, while UDP keeps each datagram as a separate message.
===END===

Yes. A p-value of 0.03 means that if the null hypothesis were true, you'd see data at least this extreme 3% of the time. That's P(data | H0), not P(H1 | data). Getting the probability that the hypothesis is true requires a prior. With a low prior plausibility or low statistical power, a p = 0.03 result can easily have a much higher than 3% chance of being a false positive. The ASA's 2016 statement on p-values calls out this exact misreading.

Switching is still correct: it wins 2/3 of the time. The 50/50 answer would hold if the host opened a door at random and it happened to show a goat. But the host knows where the car is and always opens a goat door. Your first pick has a 1/3 chance of being right, and nothing the host does changes that.
